Migration Plan: HTTP Polling → WebSocket (socket.io)
=====================================================

Context
-------
The current app uses HTTP polling to keep clients in sync with game state:
- GET /games/:id polled every 5000ms during the waiting room (Created status)
- GET /games/:id/state polled every 5000ms during active play (Ready status)

This is wasteful (constant requests even when nothing changed) and adds latency
(up to 5s delay for state updates). Migrating to socket.io enables the server to
push events immediately to all connected clients the moment state changes,
eliminating polling and improving the real-time feel.

Scope: Real-time game events only. Auth (login/register), game listing, game
creation, joining, and fetching the initial hand all stay as HTTP. The
POST /games/:id/play also stays as HTTP (action with validation), but after
processing it, the server pushes the new state to all clients via socket.


Architecture After Migration
-----------------------------
Client                         Server
  |                              |
  |--POST /auth/login---------->|   (HTTP, unchanged)
  |<--{ token }-----------------|
  |                              |
  |--socket.io connect--------->|   auth: { token }
  |  (on login, after token)     |   → JWT verified on handshake
  |                              |
  |--POST /games--------------->|   (HTTP, unchanged)
  |--GET /games/:id/join------->|   (HTTP, unchanged)
  |--GET /games/:id/hand------->|   (HTTP, unchanged)
  |--GET /games/:id/players---->|   (HTTP, unchanged)
  |                              |
  |--emit("game:join-room")---->|   subscribe to game room
  |                              |
  |           [another user joins]
  |<--emit("game:player-joined")|   { playersCount, status, ... }
  |           [4th user joins]   |
  |<--emit("game:started")------|   game is Ready
  |                              |
  |--POST /games/:id/play------>|   (HTTP, card play)
  |<--200 OK--------------------|
  |           [server updates DB]|
  |<--emit("game:state-updated")|   full IGameStateDto to all in room
  |                              |
  |--socket.io disconnect------>|   on logout / page leave


Implementation Steps
--------------------

Step 1 — Install backend packages
  File:    api/package.json
  Action:  Run: yarn add @nestjs/websockets @nestjs/platform-socket.io socket.io
           in the api/ directory.

Step 2 — Create GameGateway
  File:    api/src/games/game.gateway.ts  [CREATE]
  Action:  Implement a @WebSocketGateway with cors origin localhost:5173.
           - Inject JwtService in constructor.
           - handleConnection: extract token from client.handshake.auth.token,
             verify JWT, store userId/email in client.data, disconnect on failure.
           - handleDisconnect: no-op (socket.io auto-removes from rooms).
           - @SubscribeMessage('game:join-room'): client.join(`game:${gameId}`)
           - @SubscribeMessage('game:leave-room'): client.leave(`game:${gameId}`)
           - emitPlayerJoined(gameId, payload: GameDetailsDto): broadcast to room
           - emitGameStarted(gameId): broadcast to room
           - emitGameStateUpdated(gameId, state: GameStateDto): broadcast to room
           - emitGameDeleted(gameId): broadcast to room

Step 3 — Update GamesModule
  File:    api/src/games/games.module.ts  [MODIFY]
  Action:  - Add GameGateway to providers array.
           - Import JwtModule.registerAsync (using ConfigService / AuthConfig)
             so JwtService is available inside the gateway.

Step 4 — Update main.ts (IoAdapter)
  File:    api/src/main.ts  [MODIFY]
  Action:  - Import IoAdapter from @nestjs/platform-socket.io.
           - Call await app.init() before useWebSocketAdapter so the Fastify
             HTTP server is ready before socket.io attaches to it.
           - Call app.useWebSocketAdapter(new IoAdapter(app)).
           Note: socket.io will share the same port (3000) as HTTP.

Step 5 — Update GamesService (inject gateway, emit events)
  File:    api/src/games/games.service.ts  [MODIFY]
  Action:  - Inject GameGateway via constructor parameter.
           - In joinGame(): after saving participant, call
             gateway.emitPlayerJoined(gameId, detailsDto).
             If 4th player joined (game status → Ready), also call
             gateway.emitGameStarted(gameId).
           - In playCard(): after the DB transaction commits, build the
             GameStateDto and call gateway.emitGameStateUpdated(gameId, state).
             This covers both mid-game updates and end-game (→ Scoring) updates.
           - In deleteGame(): call gateway.emitGameDeleted(gameId) before or
             after the deletion.

Step 6 — Install frontend packages
  File:    ui/package.json
  Action:  Run: yarn add socket.io-client  in the ui/ directory.

Step 7 — Create socketService.ts
  File:    ui/src/services/socketService.ts  [CREATE]
  Action:  Singleton module managing one socket.io-client instance.
           - connectSocket(token): io('http://localhost:3000', { auth: { token } })
             Guard against double-connect if already connected.
           - disconnectSocket(): socket.disconnect(), set socket = null.
           - joinGameRoom(gameId): emit 'game:join-room'
           - leaveGameRoom(gameId): emit 'game:leave-room'
           - onGamePlayerJoined(handler): register listener, return unsubscribe fn
           - onGameStarted(handler): register listener, return unsubscribe fn
           - onGameStateUpdated(handler): register listener, return unsubscribe fn
           - onGameDeleted(handler): register listener, return unsubscribe fn

Step 8 — Create gameSocketSlice.ts and add to store
  File:    ui/src/store/slices/gameSocketSlice.ts  [CREATE]
  File:    ui/src/store/index.ts  [MODIFY]
  Action:  Create Redux slice with state:
             { gameState: IGameStateDto | null, playersCount: number | null,
               gameStatus: TGameStatus | null }
           Reducers: setGameState, setPlayersCount, setGameStatus,
                     clearGameSocketState.
           In store/index.ts: add gameSocket reducer to the store's reducer map.

Step 9 — Auth integration (connect/disconnect socket)
  Files:   ui/src/store/api/authApi.ts  [MODIFY]
           ui/src/store/index.ts  [MODIFY]  (listenerMiddleware)
           ui/src/components/AuthInitializer.tsx  [MODIFY]
  Action:  - authApi.ts: in onQueryStarted callbacks for login and register,
             after dispatching setCredentials, call connectSocket(data.accessToken).
           - store/index.ts listenerMiddleware: the existing logout() listener
             (which already resets RTK Query cache) should also call
             disconnectSocket().
           - AuthInitializer.tsx: after re-hydrating credentials from
             GET /users/profile on page refresh, call connectSocket(token)
             so the socket reconnects when the user returns to the app.

Step 10 — Update GameRoom (replace polling with socket events)
  File:    ui/src/pages/GameRoom/index.tsx  [MODIFY]
  Action:  Remove:
           - pollingInterval / statePollingInterval state variables
           - useGetGameStateQuery hook call
           - useEffect that adjusts polling intervals based on game status
           Add:
           - useEffect on mount: joinGameRoom(gameId), cleanup leaveGameRoom(gameId)
           - useEffect for onGameStateUpdated: dispatch setGameState(state)
           - useEffect for onGamePlayerJoined: dispatch setPlayersCount(details.playersCount)
           - useEffect for onGameStarted: dispatch setGameStatus('Ready'),
             call refetchHand() and refetchPlayers()
           - useEffect for onGameDeleted: navigate('/')
           - Read gameState from useAppSelector(state => state.gameSocket.gameState)
             instead of from RTK Query.
           - useGetGameQuery called once on mount (no polling) for initial metadata.

Step 11 — Remove getGameState from gamesApi.ts
  File:    ui/src/store/api/gamesApi.ts  [MODIFY]
  Action:  - Remove the getGameState endpoint entirely (state now arrives via socket).
           - Keep getGame but remove any polling usage.
           - All other endpoints (getPlayers, getHand, playCard, etc.) unchanged.

Notes
------
- Fastify + socket.io: IoAdapter attaches socket.io to the Node.js HTTP server
  that Fastify uses internally. await app.init() must precede useWebSocketAdapter.
- CORS for socket.io must be set in @WebSocketGateway({ cors: ... }), separately
  from Fastify's app.enableCors().
- No circular dependency: GamesService → GameGateway → JwtService (from JwtModule).
- HTTP play endpoint stays: POST /games/:id/play remains HTTP for clean validation.
  The socket broadcast happens inside the service after the DB write.
- Token storage: frontend already uses sessionStorage. AuthInitializer reconnects
  the socket on page refresh after re-hydrating credentials.
